# QVision v0.9 — code audit

Scope: everything under `App/Sources` as of v0.8.1 (commit 9120b33), about 11,700 lines.
Line numbers refer to the v0.9 sources. Nothing here was run on a device: the findings come from reading the code, and the fixes are verified by the CI build only.

Severity: **High** = can lose the session or a lot of memory; **Medium** = visible glitch or wasted resources; **Low** = cosmetic or theoretical.

## Fixed in v0.9

| # | Sev. | Where | Defect | Fix |
|---|---|---|---|---|
| M1 | High | `Stage/StageController.swift:49` (`environments`), `Stage/EnvironmentBuilder.swift` caches | Every environment a project ever showed (sky, PBR floor, IBL, sun) stayed in memory for the life of the app, and so did the shared texture caches. Opening a rendered scene after a project started with that memory already taken. | `StageController.releaseEnvironments()` (line 899) runs in `AppModel.closeProject` (line 404). `EnvironmentBuilder.purgeCaches()` (line 183) runs there and in `RenderedViewer.release` (line 155). Environments are rebuilt on demand. |
| M2 | High | `Rendered/RenderedViewer.swift:137` (`begin`) | Two scenes could be in memory at once. A load that is inside RealityKit cannot be cancelled, so leaving during a load and opening another scene started the second load while the first was still running. | `begin` now waits for the previous load task to finish (it is dropped immediately) before it starts the next one. |
| F1 | Medium | `Core/AppModel.swift:1415` (`renderedDidDisappear`) | A late `onDisappear` from the previous rendered space could release the scene the flow had just started loading. | The scene is released only when no scene is current or no transition is running. |
| F2 | Medium | `Input/HandTrackingService.swift` (`start` / `stop`), three immersive views | The three spaces share one hand-tracking service and each stopped it in `onDisappear`. A late disappear of the old space could stop tracking for the new one: no palm menu and no fly. v0.8 worked around it in Rendered with a watchdog. | `start(owner:)` / `stop(owner:)`: tracking stops only when no owner is left. |
| D1 | Medium | `UI/RootView.swift:199` (`loadingOverlay`) | "Opening project…" had no way out while a big model loaded. | Cancel button (leaves the project). |
| D2 | Medium | `Rendered/RenderedSessionView.swift` | A failed scene load offered only "Try again" and an Exit button whose label did not say where it went. | Retry, plus one button that reads Cancel / Back to Home / Exit scene depending on the state. |
| D3 | Medium | `Rendered/RenderedHomeView.swift` | "It doesn't connect": the tab needed a Connect tap, and a failure showed a generic network message. | Connects by itself and retries every 4 s while visible. The message says what to start on the PC and shows the address being tried. `/health` tells a wrong address from a stopped library. |
| D4 | Medium | `Rendered/RenderedLibrary.swift` (downloads) | An interrupted download threw away everything and started again from zero. | Resumable transfer with HTTP Range (`ResumableTransfer`, line 543). The partial file is kept in `.resume-<id>/`. |
| P1 | Low | `Rendered/RenderedModels.swift` (`LibraryEntry.modifiedDate`) | A new `ISO8601DateFormatter` was created for every row on every redraw. | One shared formatter. |
| U1 | Low | `Stage/StageView.swift`, `Rendered/RenderedImmersiveView.swift` | Two separate palm-menu implementations with different position, grace time and look. | One implementation in `UI/PalmMenu.swift`, used by all three spaces. |
| U2 | Low | 16 places | Text smaller than the system footnote size (`.caption`, `.caption2`). | All replaced with `.footnote`. |

## Left as it is (with the reason)

| # | Sev. | Where | Risk | Why not now |
|---|---|---|---|---|
| L1 | Medium | `Core/AppModel.swift:1204` (`stageDidDisappear`), `:1415` | If the old space's `onDisappear` arrives after the next space's `onAppear`, `stageState` / `renderedState` is set to `.closed` while a space is open. The flow would then try to open a second space and show "couldn't be opened". In practice `dismissImmersiveSpace()` returns after the disappear, so this needs unusual timing. | A correct fix needs a generation token passed through the view's lifecycle. If the tab is not on screen when the stream ends, only the 0.6 s fallback in `StreamImmersiveView` closes the space. | Moving it into AppModel touches the CloudXR connect sequence, which follows NVIDIA's sample and works. The Continue card switches to the Server tab before connecting for this reason. |
| L3 | Low | `Core/AppModel.swift:1631` (`persist`), `Core/ProjectStore.swift:97` | Every project change writes `project.json` synchronously on the main actor. | The file is a few kilobytes and slider changes are already debounced. |
| L4 | Low | `Core/AppModel.swift:307`, `Rendered/RenderedLibrary.swift:94` | Projects and rendered scenes are listed synchronously at launch and on refresh (directory listing plus small JSON files). | Milliseconds for the handful of items expected. | L6 | Low | `Rendered/RenderedViewer.swift` (`prepare`) | Material conversion runs on the main actor (it yields every 150 entities). | RealityKit components must be changed on the main actor. |
| L7 | Low | `Stage/StageController.swift` (1,360 lines), `Core/AppModel.swift` (1,750 lines) | Large files that mix several responsibilities (undo, places, flow, units). | Refactoring without a compiler or a device is all risk and no user benefit. |

## Checked and found sound
- **Serialized flow.** Open and leave for projects and rendered scenes go through one queue (`enqueueFlow`), and each `sync…` loop is bounded and never leaves a state stuck in `.transitioning`.
- **Closing the last window.** Both project and rendered paths wait 450 ms for a window that is opening, then leave without reopening Home.
- **Downloads.** A scene folder appears only after its size is verified and the folder is renamed into place. Leftover `.partial-*` folders are removed at launch.
- **File copies and USDZ loads.** Imports copy off the main actor with file coordination. `Entity(contentsOf:)` loads asynchronously.
- **Crash sources.** No `try!`, `fatalError`, `as!` or synchronous main-queue dispatch anywhere in the sources.
