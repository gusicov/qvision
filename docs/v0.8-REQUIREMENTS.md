# QVision v0.8 — Rendered mode + max-quality Server (orchestrator decisions)

User request (2026-11-15):
- **Server:** on the server it should run live, with Lumen, at the highest quality available.
- **New mode in the headset app**, alongside Server and normal Projects: a "rendered" mode. One fully baked model runs only on the headset. Use the most efficient method for both. The orchestrator decides.

## R1 — Three ways to view a model (Home tabs)

| Tab | What | Lighting | Runs on |
|---|---|---|---|
| **Projects** | edit/arrange any USDZ (as today) | RealityKit real-time (IBL + grounding) | headset |
| **Rendered** *(new)* | walk through one photoreal pre-lit scene | **baked into textures** (path-traced offline), shown **unlit** | headset only, offline after download |
| **Server** | Unreal stream via CloudXR | live (Lumen on big GPUs, baked on the PC) | PC / office server |

Why baked and unlit for Rendered:
- Path-traced global illumination at a fixed cost: the headset only samples textures, so 90 fps is easy and the image is identical in both eyes.
- No temporal noise, no shimmer.
- It needs no network once downloaded, so it works anywhere and is ideal for presentations.
- Gaussian splats were considered and rejected for v0.8:
  - training them needs hundreds of renders and a GPU pipeline;
  - they behave poorly when flying through interiors;
  - native visionOS splat rendering means a separate Metal/CompositorServices renderer.
  - We may revisit them later for exterior or "hero" captures.

## R2 — Baked scene format ("QVision Rendered package")
- **Files:**
  - `<Name>.usdz` (Y-up, metres);
  - optional sidecar `<Name>.json`;
  - optional `<Name>.jpg` thumbnail (≤ 512 px).
- **USDZ content:**
  - Every visible surface's material carries its **final lit colour** as the base-colour texture, in sRGB, already tone-mapped and exposed.
  - Glass and other transparents carry an opacity value or texture.
  - Normal and roughness maps are ignored.
- **Sidecar JSON:**
  ```json
  { "title": "Casa SUA", "version": 1,
    "start": { "position": [x, y, z], "yawDegrees": 0 },
    "eyeHeightIncluded": false,
    "notes": "baked with Blender Cycles ..." }
  ```
  - `start.position` is a floor-level point in USDZ coordinates (metres). The user's feet go there.
- **Budgets** (so the scene fits comfortably in headset memory at 90 fps):
  - ≤ ~1.5 M triangles;
  - ≤ 8 atlases of 4096² (plus small extras);
  - USDZ ≤ ~500 MB.
- **Producers:** Blender Cycles bake now (`tools/bake/`). Later, 3ds Max + Corona render-to-texture into the same format.

## R3 — Delivery: QVision Library on the PC (no iCloud, no public repo)
Client models must never go into the public GitHub repo or the IPA.

- A tiny **library server** on the PC (`tools/library-server/qvision_library.py`): Python stdlib only, `ThreadingHTTPServer`, port **8770**.
  - It serves the folder `C:\All Docs\06_Apple vision pro\assets\Rendered\`.
  - `GET /index.json` returns `[{ "id", "title", "file", "sizeBytes", "modified", "thumbnail"?, "sidecar"? }]`, regenerated from the folder.
  - `GET /files/<name>` streams a file.
  - It only allows LAN clients.
- A firewall rule (Private profile, LocalSubnet, TCP 8770). The user runs it once as admin.
- Desktop shortcut **`Desktop\Vision Pro\QVision Library (PC).lnk`**.
- **The app:**
  - The Rendered tab lists "On this Vision Pro" (downloaded) and "On my PC" (library index).
  - The PC address comes from the saved Server entry ("My PC"), editable.
  - Download with progress into `Documents/Rendered/`, then use offline.
  - Delete frees space.
  - Also **Import from Files** (USDZ + sidecar optional) for future use.

## R4 — Rendered viewer (app)
- A dedicated **ImmersiveSpace "rendered"**, `.full` immersion by default; mixed is optional.
- It reuses HandTrackingService and FlyController for fist-fly.
- On load:
  - Load the USDZ off the main actor, with a progress/spinner.
  - Convert **every** material to `UnlitMaterial` keeping the base-colour texture/tint and the opacity (blending for glass).
  - Add no lights, no IBL and no grounding shadows; keep it cheap.
- Placement:
  - Real scale (1:1).
  - The scene is positioned so `start.position` is under the user's feet and `start.yawDegrees` faces forward.
  - With no sidecar, use the bounds centre at floor level.
- Controls:
  - Fist-fly as in Projects (same speed curve, slider 1×–10×), plus **Reset to start**.
  - A small palm or hand menu with Exit / Start position / Speed.
  - No editing.
- Sky: if the scene has no sky geometry, show the existing baked sky dome (EnvironmentBuilder daylight) far away.
- App flow (L6 rules):
  - Leaving returns to Home › Rendered.
  - Closing the last window exits cleanly.
  - Nothing gets stuck.
- Memory:
  - Load one rendered scene at a time.
  - Release it fully when leaving.
  - If loading fails, show a clear error (file too big, unsupported).
- `Info.plist`: `NSAppTransportSecurity` → `NSAllowsLocalNetworking = true` (HTTP to the PC on the LAN).

## R5 — Server: max-quality live profile (Unreal)
- New profile **`-qvquality=max`**:
  - deferred renderer;
  - **Lumen GI + reflections, hardware ray tracing** (hit-lighting reflections where affordable);
  - live sun/sky (the `Casa_SUA_Lumen` map), Virtual Shadow Maps;
  - TSR with stereo-friendly settings that minimise per-eye temporal noise (research what works for VR);
  - the headset gamma/exposure fix from v0.9 kept.
- **Auto-select:**
  - if the GPU has ≥ 32 GB VRAM (the office Blackwell 96 GB), `max` is the default;
  - on the user's RTX 3070 the default stays **VR Ultra (baked)**. Lumen at about 45 fps glitched in the headset.
  - `-qvquality=` always overrides.
- Must be packaged (cooked) with both maps, and test-run on the 3070 for correctness (frame rate there is informative only). Document the expected cost on the office GPU.

## Execution order (one GPU, 8 GB)
1. Blender Cycles bake (GPU), in parallel with the app work (CI only, no GPU).
2. Then the Unreal `max` profile (GPU).
3. The orchestrator reviews the bake previews and the CI build. Then the user test: start Library → Rendered → download Casa SUA → open.
