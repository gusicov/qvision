# QVision v0.11: Quantities (orchestrator decisions)

User request (2026-11-23): add a Projects & Quantities section to the app. The user's ZIP (`ArchViewer_CAMPUS_BLOC.zip`, extracted to `C:\All Docs\06_Apple vision pro\assets\Quantities\ArchViewer_CAMPUS_BLOC\`) holds two projects, CAMPUS and BLOC. Each has a layered USDZ, a light context USDZ, an Excel workbook, an article catalogue and JSON links between articles and model elements. The ZIP's own `CLAUDE.md` is the integration brief; three Swift files at its root (`ArchViewerQuantityData.swift`, `ArchViewerQuantities.swift`, `ArchViewerArticlePanel.swift`) do the package loading, hatching and article panel.

The user wants to:
- choose a project;
- search articles by name and see the exact quantity and unit;
- select an article: its elements show hatched at 100% opacity and the rest of the building dims to **20%** (not the 10% in the ZIP brief: the user's number wins);
- **control how much of the building they see**: a prominent opacity slider for the rest of the building, always visible, not hidden in a disclosure group;
- rotate the whole model together;
- tap an element to see its articles.

## Q1: Delivery (client data never goes into the repo or the IPA)
- The QVision Library server (`tools/library-server/qvision_library.py`, port 8770) also serves quantity packages from `C:\All Docs\06_Apple vision pro\assets\Quantities\`.
  - A package is any folder up to 3 levels deep that holds a `manifest.json` with `schemaVersion` 1 and a `packageId`.
  - `GET /quantities.json` → `[{ "folder", "packageId", "name" (manifest `projectName`), "files": {path: {bytes, sha256}}, "sizeBytes", "modified" }]`. Only the files the app needs: drop `Preview/` and `Reference/`.
  - `GET /q/<folder>/<relative path>` streams a member, with Range support. Traversal is refused, as with `/files/`.
  - `/health` gains `"quantities": N`.
- App: download a package into `Documents/Quantities/<packageId>/`, keeping relative paths, with progress, resume and Update (the same behaviour as Rendered), then open it with `AVQPackage.open(at:)`, which checks every SHA-256.
- IDs and caches are scoped by `packageId`. Some article IDs occur in both projects.

## v0.11.1: never load the main per-element USDZ on the headset
Headset test: BLOC stayed on "Loading the model…" for over 10 minutes. The main USDZ has one mesh per element (BLOC 17,831 meshes, CAMPUS 21,422), which RealityKit can't load in reasonable time. The context USDZ holds the same triangles merged per layer and material (BLOC 508 meshes, CAMPUS 589).
- **PC:** `tools/quantities/qv_pick.py` (`Build-QuantityPick.cmd`, Blender's Python for `pxr`) writes `Data/pick.json` + `Data/pick.bin` per package: welded triangles of every context mesh (model metres, Y up, world transforms applied) and a per-triangle index into an `elementIds` table (0xFFFFFFFF = unknown). Triangles map to elements by their 1 mm centroid (same layer first, coincident faces shared out one to one), then by the nearest centroid within 5 mm. The package's `manifest.json` is not changed.
- **Library:** `/quantities.json` lists `Data/pick.json` and `Data/pick.bin` when present and no longer lists the main model (`model.path`) when the package has a context model.
- **App:** `AVQPackage.open` no longer needs the main model and checks sizes only (hashes are checked once, at download). The context USDZ is the `building` (no `reviewContext`), so dimming, hatching and opacity apply to it. Layer toggles enable the layer Xforms by `AVQLayer.entityName`. Static mesh collision shapes for the context meshes are built in batches ("Preparing taps N %"). A tap converts the hit into model space, finds the nearest triangle of the hit mesh in the memory-mapped `pick.bin` (a grid per mesh, built on its first tap), and shows that element's articles (walking `parentElementId` up when it has none). A download without `pick.bin` shows Update. The loading text shows the elapsed seconds.
- **Version:** 0.11.1 (build 14).

## v0.11.2: direct manipulation, Lock model, the window wins, list only, no Environments
Headset feedback on v0.11.1.
- **Manipulation:** the Move handle and its label are gone. Gestures on the RealityView, targeted to any entity, all applied to `placement`:
  - one hand, pinch and drag on the model: it moves freely in 3D (the scene-space delta of the pinch; a 1.2 cm dead zone so a tap never moves it);
  - `MagnifyGesture` (two hands): scale;
  - `RotateGesture3D(constrainedToAxis: .y)` (two hands turning): yaw (the angle signed by `axis.y`);
  - a two-hand gesture undoes the first hand's drag and takes over; when it ends while one hand still pinches, the drag goes on from there;
  - `SpatialTapGesture` still selects; taps during a drag, a two-hand gesture or within 0.3 s after one that changed the model are ignored.
  - Recentre and the scale presets stay in the window (Recentre also on the palm).
- **Lock model** (window header, lock icon, persisted as `qv.quantities.lockModel`): sets `InputTargetComponent.isEnabled = false` on the building (its per-mesh collision shapes inherit it), the coarse grab volume and the selection overlay (`ArchViewerQuantities.setOverlayInput`, also for overlays built later); every gesture handler ignores input while locked.
- **The window wins:** an immersive space can't read window positions. The quantities window opens with the default placement, straight ahead of the user (about 1.1 m wide), and Recentre is pressed from that window, so head-forward points at it. Placement (load and Recentre) therefore puts the model front-right: centre at `max(0.9 m, radius + 0.45 m)`, turned round by the window's half-angle (~24°) + the model's own angular radius + ~5° (at most ~72°), base at eye height − 0.7 m (0.45–0.9 m). The model is never between the user and the window. If the user drags it there later, Recentre moves it clear again, and Lock model makes it transparent to input so the window gets every pinch.
- **Article panel:** the right-hand detail column ("Select an article") is gone; the list takes the full width (code, title, position, `displayQuantity` + unit). The selected row stays highlighted and scrolls into view when a model tap chooses it. Normal view, search and the zone filter stay; a small line shows "Preparing preview" or an error. The tapped-element card stays.
- **Rendered:** the Environments section is removed (`EnvironmentsSection.swift` deleted). `kind: environment` packages are hidden from "On this Vision Pro" and "On my PC"; at launch `RenderedLibrary` deletes every downloaded Environment package from Documents. The viewer's Environment code paths stay but are unreachable.
- **Version:** 0.11.2 (build 15).
