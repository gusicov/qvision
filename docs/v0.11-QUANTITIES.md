# QVision v0.11: Quantities (orchestrator decisions)

User request (2026-11-23): add a Projects & Quantities section to the app. The user's ZIP (`ArchViewer_CAMPUS_BLOC.zip`, extracted to `C:\All Docs\06_Apple vision pro\assets\Quantities\ArchViewer_CAMPUS_BLOC\`) holds two projects, CAMPUS and BLOC. Each has a layered USDZ, a light context USDZ, an Excel workbook, an article catalogue and JSON links between articles and model elements. The ZIP's own `CLAUDE.md` is the integration brief; three Swift files at its root (`ArchViewerQuantityData.swift`, `ArchViewerQuantities.swift`, `ArchViewerArticlePanel.swift`) do the package loading, hatching and article panel.

The user wants to:
- choose a project;
- search articles by name and see the exact quantity and unit;
- select an article: its elements show hatched at 100% opacity and the rest of the building dims to **20%** (not the 10% in the ZIP brief: the user's number wins);
- **control how much of the building they see**: a prominent opacity slider for the rest of the building, always visible, not hidden in a disclosure group;
- rotate the whole model together;
- tap an element to see its articles.

## Q1: Delivery (client data never goes into the repo or the IPA)
- The QVision Library server (`tools/library-server/qvision_library.py`, port 8770) also serves quantity packages from `C:\All Docs\06_Apple vision pro\assets\Quantities\`.
  - A package is any folder up to 3 levels deep that holds a `manifest.json` with `schemaVersion` 1 and a `packageId`.
  - `GET /quantities.json` → `[{ "folder", "packageId", "name" (manifest `projectName`), "files": {path: {bytes, sha256}}, "sizeBytes", "modified" }]`. Only the files the app needs: drop `Preview/` and `Reference/`.
  - `GET /q/<folder>/<relative path>` streams a member, with Range support. Traversal is refused, as with `/files/`.
  - `/health` gains `"quantities": N`.
- App: download a package into `Documents/Quantities/<packageId>/`, keeping relative paths, with progress, resume and Update (the same behaviour as Rendered), then open it with `AVQPackage.open(at:)`, which checks every SHA-256.
- IDs and caches are scoped by `packageId`. Some article IDs occur in both projects.

## Q2: App: a new **Quantities** tab on Home (Projects · Rendered · Server · Quantities)
- **Project list:** cards for CAMPUS and BLOC ("On this Vision Pro" / "On my PC", as in Rendered), with Download / Open / Update / Delete.
- **Open** starts a **mixed** ImmersiveSpace `quantities` and shows the quantities window.
  - Scene graph: `placement` (the movable parent) → `building` (the main USDZ, named) + the overlay and context, which `ArchViewerQuantities` adds.
  - The context USDZ is loaded unattached and passed as `reviewContext`.
- **Placement:**
  - The model sits as a table-top model: scale it so the largest horizontal extent is about 1.2 m, centre it about 1 m in front of the user, with the base at about 0.9 m height.
  - Scale presets: Table (fit), 1:200, 1:100, 1:50, plus pinch-to-scale.
  - A drag on the model rotates the whole `placement` about its vertical axis; a two-hand gesture or a "Move" handle repositions it.
  - Movement, rotation and scale always go on `placement` only, so the model, hatch and context stay together.
  - Recentre button.
- **Window** (the existing design system):
  - Project switcher at the top. Switching project calls `detach()` on the active viewer, clears the selection, unloads the old entities, then loads the new one.
  - `ArchViewerArticlePanel` with the app's selection binding: search by name, code or row; zone/building filter; Romanian titles, reference, exact `displayQuantity` + unit, status, levels, part stepping.
  - **"Building visibility" slider**, 0–100%, default 20%, in the window header, always visible, applied with `setContextOpacity`. Also a "Show whole building" toggle that returns to normal view.
  - Building toggles from the manifest (`buildings` for CAMPUS; layers for BLOC if a top-level split exists), mirrored into `AVQVisibility.hiddenLayerIds` and applied to the entities.
- **Tap an element:**
  - Use `SpatialTapGesture().targetedToAnyEntity()` → `viewer.element(forHit:)` → `package.usesByElement[elementId]`.
  - Show that element's articles (primary, hosted, reference-only, reviews), each with title, quantity and unit.
  - Choosing one selects it.
  - When the tap lands on the hatched overlay, also use `parts(atProjectPoint:)` (convert the hit to building/model coordinates first) to pick the exact part.
  - Collision shapes for picking: generate them off the main actor in batches after the model shows (static mesh where affordable, otherwise boxes from the bounds). Never block the first frame. CAMPUS has about 21k meshes and 1.3 M triangles.
- **Changes to the ZIP's Swift files:** keep them as provided, except:
  - the default context opacity is 0.20 (the viewer's `contextOpacity` and the panel's `opacity`);
  - the panel's opacity slider can move to the window header, since the host owns that state; pass it in or expose a binding.
  - Keep them in `App/Sources/Quantities/`.
- **Memory:**
  - Only one project is loaded at a time; release everything when leaving or switching.
  - The palm menu (left palm) offers Exit · Recentre · Normal view.
- **Version:** 0.11.0 (build 13).
