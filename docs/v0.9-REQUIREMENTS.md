# QVision v0.9 — audit + polish (orchestrator decisions)

User request (2026-11-16): audit the app, decide the improvements and make them: UI, how the app starts and runs, flow. The user's verdict so far: baked **Rendered** mode is the favourite (best look, perfectly fluid). The pain points seen in testing:
- twice "it doesn't connect", because the PC library was not running;
- three modes that each behave a little differently;
- no quick way back into the scene you were in.

## A — Code audit (the agent does it first, writes `docs/v0.9-AUDIT.md`)
Read all of `App/Sources`. List real defects and risks, each with file:line, severity and a fix. Fix everything that is cheap and safe; list what you leave. Look especially for:
- window / immersive-space flow races (open, leave, relaunch, scene restoration, closing the last window);
- memory (textures and entities kept after leaving a scene; two scenes loaded at once);
- main-actor blocking work (file copies, JSON, USDZ load);
- error paths that leave a spinner or a dead screen;
- dead code and duplicated logic between Projects / Rendered / Server.

## B — Start and run (the app should get you into a scene in one tap)
- B1. **Continue** card at the top of Home: the last thing opened (project, rendered scene or server), one tap to reopen it. Persist it.
- B2. Home opens on the tab used last.
- B3. Rendered scenes remember where you were: on reopening offer the last position (default) or the start; per scene, persisted.
- B4. Never a dead end: every loading state has Cancel, every failure has Retry and Back to Home.

## C — Rendered tab and library (the favourite mode, make it effortless)
- C1. Connect automatically when the tab appears (saved address), with a quiet retry every few seconds while the tab is visible. No Connect button needed in the normal case.
- C2. When the PC does not answer, say exactly what to do: "Start **QVision Library (PC)** on your PC (Desktop › Vision Pro). It now also starts with Windows." Show the address being tried and keep it editable.
- C3. **Updates**: when the PC copy of a downloaded scene is newer (index `modified` / `sizeBytes` differ from what was downloaded), show an **Update** badge and button. Store the downloaded `modified` and `sizeBytes` next to the scene.
- C4. Downloads resume after an interruption (HTTP Range; the server supports adding it — see E) or at least restart cleanly; show MB and percentage.
- C5. Cards: larger thumbnail, title, size, "HD" badge when the sidecar has `"shading": "hd-lightmap"`, date, and a clear primary action (Open / Download / Update).

## D — In-scene controls, the same in all three modes
- D1. One palm menu design (left palm toward you) for Projects, Rendered and Server: same position, same look, same order. Primary row: **Home/Exit · Viewpoints (Rendered) or Panel (Projects) · Speed**. Show only what applies.
- D2. **Viewpoints** (Rendered): the sidecar now has
  ```json
  "viewpoints": [ { "name": "Kitchen", "position": [x, y, z], "yawDegrees": 0 } ]
  ```
  (same conventions as `start`: floor level, USD metres, yaw about +Y from −Z). Show them as a list in the palm menu and in the session window; choosing one moves the user there with a short fade (no sliding motion — comfort). "Start" is always the first entry. Missing key = just Start.
- D3. Speed: three presets (Walk 1×, Fast 3×, Fly 10×) plus the slider, remembered per mode.
- D4. Comfort: an optional vignette while flying fast (default on, toggle in Settings).
- D5. The "HD shading: N · M baked" line stays, in the session window's details, not in the palm menu.

## E — Library server (`tools/library-server/qvision_library.py`)
- E1. Support `Range` requests (206) so downloads can resume.
- E2. `GET /health` → `{ "name": "QVision Library", "version": 2, "scenes": N }` so the app can tell "server up" from "wrong address".
- Test locally (full file, ranged file, health, traversal still refused).

## F — Settings / About (new, small)
- App version and build.
- **Days left on the 7-day signing**: read `embedded.mobileprovision` in the bundle (plist inside the CMS blob, key `ExpirationDate`); show "Expires in N days — re-install with iloader before then". If it cannot be read, hide the line.
- Storage used by downloaded scenes and projects, with "Free up space".
- Comfort toggles (D4), default fly speed.
- Short "How to" (fists to fly, left palm for the menu).

## G — Visual polish
- One consistent design language from `DesignSystem.swift` across Projects, Rendered and Server (headers, cards, pills, empty states). Empty states say what to do next.
- No text smaller than the system footnote size; primary actions are prominent and at least 60 pt tall.

## Rules
- visionOS 2.0 deployment target; `#available` guards for anything newer; no `restorationBehavior`.
- Cannot run on device here: prefer simple, well-understood APIs. Keep the working flows (serialized open/leave in AppModel) intact.
- Version **0.9.0 (build 11)**. CI green, IPA copied to `Desktop\Vision Pro\QVision.ipa`.
- Never commit client paths or names; `tools/bake/casa_sua.json` is git-ignored.
